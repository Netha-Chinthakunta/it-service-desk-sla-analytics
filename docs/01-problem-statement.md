# Problem Statement

An IT support team is drowning in tickets with no clear visibility into SLA breaches, agent workload balance, or recurring root causes. 
Leadership needs to know: are we meeting SLAs, where are the bottlenecks, and which categories, agents, or time periods are driving the most breaches — so staffing and prioritization decisions can be made with evidence instead of guesswork.

This project answers that question end-to-end: generating realistic ticket data, cleaning and modeling it in SQL, and building a Power BI dashboard that turns raw incident data into a clear, actionable story.

# Why This Project

I currently work as an EUC Analyst at Channel 4, where I deal with incident tickets, SLAs, and service desk workflows as part of my day-to-day role. 
This project isn't a random dataset picked off a template — it's a synthetic recreation of the kind of data and questions I already work with, rebuilt from scratch to demonstrate that I understand the domain, not just the tools.

I'm building this as part of my transition into a data analyst role, alongside working toward the PL-300 (Power BI Data Analyst) certification. 
I want this project to show that I can take a real operational problem, structure it properly in SQL, and communicate the findings clearly in Power BI — the full path from raw data to a decision someone could actually act on.
